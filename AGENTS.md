# AGENTS.md

XS bindings for the Clay v0.14 C UI layout library. Single distribution,
header-only C dependency, no system libraries.

## Build and test

```
perl Makefile.PL && make && make test
```

Useful invocations:

| Need                                    | Command                                                               |
|-----------------------------------------|-----------------------------------------------------------------------|
| Single test                             | `prove -lvb t/04-elements.t`                                          |
| Regenerate golden fixtures              | `CLAY_UI_UPDATE_FIXTURES=1 prove -lb t/99-golden.t`               |
| Disable SIMD probe (exotic platforms)   | `PERL_CLAY_DISABLE_SIMD=1 perl Makefile.PL`                            |
| Run an example                          | `perl -Ilib -Iblib/lib -Iblib/arch examples/01-minimal.pl`            |

`prove` requires `-lb` because the loadable XS object lives under `blib/arch/`.

## Source layout

- `lib/Clay/XS.xs`, `src/*.c`, `src/clay_perl.h` - the binding.
  `src/clay_impl.c` compiles the Clay implementation plus the few
  helpers that read Clay internals (declared in the Perl-free
  `src/clay_impl_helpers.h`).
- `src/clay/clay.h.orig` - **pristine** vendored Clay v0.14 header. Committed.
  The actual build copy `src/clay/clay.h` is generated by `make` from
  `clay.h.orig` plus the patches under `patches/`; `clay.h` is gitignored
  so the working tree stays clean.
- `patches/0001-clay-sizing-groups.patch` - vendored patch adding the
  `sizingGroup` field to `Clay_ElementDeclaration`, the
  `CLAY_ERROR_TYPE_SIZING_GROUP_CYCLE` error type, and
  `Clay__ApplySizingGroups`, called from `Clay__CalculateFinalLayout`
  before each axis is distributed. Per axis and frame it alternates
  "equalize members to their group's largest size (capped at each
  member's own max)" and "re-aggregate FIT/GROW containers and their
  minimum sizes bottom-up" until nothing changes (nested groups), with a
  round cap that reports cyclic nesting. It equalizes once per frame:
  the second `Clay__CalculateFinalLayout` pass that transitions trigger
  only restores members to the sizes of the first pass. Group lookup is
  an open-addressing hash in Clay's per-frame arena.
- `references/clay/` - the upstream repo kept for reference only. Not in the
  build path. Do not edit; do not assume edits there propagate.
- `t/fixtures/*.pl` + matching `.json` - golden-output harness used by
  `t/99-golden.t`. Each `.pl` returns a coderef that builds a layout and
  returns the render-command arrayref. Most use Clay::XS directly;
  `09-ui-tree.pl` goes through Clay::UI and replaces each command's
  `userData` (a refaddr) with the widget's class and id.

## Build invariants that look weird but are deliberate

1. **`Makefile.PL` has a `postamble` adding `src/%.o : src/%.c`.** EUMM's
   default `.c.o` suffix rule omits `-o $@`, so gcc dumps subdirectory
   objects into the CWD and the link step fails. Removing the postamble
   breaks the build.
1a. **The same postamble has a rule
    `src/clay/clay.h : src/clay/clay.h.orig patches/...patch`** that
    runs `patch -o src/clay/clay.h.tmp` on the pristine header and moves
    the result into place only when `patch` succeeds, so a failed patch
    never leaves an up-to-date-looking, unpatched `clay.h`. Object files
    declare an explicit dependency on `src/clay/clay.h` so the rule fires
    before compilation. Touching the patch file forces a re-generation.
    `make clean` deletes `src/clay/clay.h`; the next `make` re-derives it.
2. **`typemap` maps `uint32_t`, the only fixed-width type used as an XS
   return type.** Without it `xsubpp` fails with "Could not find a typemap
   for C type 'uint32_t'". Arguments are taken as `SV *` and range-checked
   by the parsing helpers in `src/marshal.c`, so they need no entries.
3. **`#define CLAY_IMPLEMENTATION` lives in exactly one file:
   `src/clay_impl.c`.** Every other `.c` (and `lib/Clay/XS.xs`) includes
   `clay/clay.h` without the define. `src/clay_impl.c` also holds the
   binding helpers that need Clay's internals (`struct Clay_Context`,
   the default counts, the arena routines): exit-transition detection
   and the 64-bit arena-size bound. It includes no Perl headers.
   Bumping Clay requires preserving this pattern and re-checking those
   helpers against the new internals.
4. **`src/clay_impl.c` brackets its include in `#pragma GCC diagnostic
   ignored` lines.** Upstream Clay v0.14 emits `-Wunused-variable`,
   `-Wunused-function`, `-Wsign-compare` and `-Wmissing-field-initializers`
   under `-Wall -Wextra`. The
   suppression must travel with any clay.h bump.
5. **`PERL_NO_GET_CONTEXT` is defined in `src/clay_perl.h`.** Every
   helper takes `pTHX_` and every call passes `aTHX_`; trampolines that
   Clay calls fetch the interpreter with `dTHX`. New helpers must follow
   the same convention or the build fails.

## Runtime invariants and Clay-API traps

1. **`xs_ctx_DESTROY` calls `Clay_SetCurrentContext(NULL)` before freeing
   the arena.** Clay's `Clay_Initialize` reads `oldContext->maxElementCount`
   of the current context. Without the reset, the next `Clay_Initialize`
   dereferences freed memory. If you see SIGSEGV on the second
   `Clay_Initialize`, this is the cause.
1a. **A context is owned by one referent.** The `Clay::XS::Context`
   object is a reference to a read-only scalar carrying the context
   pointer in private ext magic (`src/clay_perl_context.c`).
   `Clay_GetCurrentContext` hands out another reference to the same
   referent, so DESTROY runs once; DESTROY clears the magic pointer, so a
   second explicit DESTROY is a no-op. Copies and forged objects have no
   magic and croak. `Clay::XS::Context::CLONE_SKIP` keeps contexts out of
   new threads, and each context records its interpreter: using it from
   another one croaks.
2. **`Clay_SetPointerState` walks the previous frame's layout tree to
   populate `pointerOverIds`.** Pointer-over assertions need at least one
   prior `EndLayout`. See `t/06-pointer.t` for the two-frame pattern.
3. **Wheel-based scrolling only applies when the pointer is over the
   scroll container.** `Clay_UpdateScrollContainers` picks the highest
   priority element from `pointerOverIds`. See `t/07-scroll.t`.
4. **Per-element transition callbacks are NOT supported.** Clay's transition
   callback signatures lack an element id. Use `Clay_SetTransitionHandlers`
   to install one handler set per context; the handler must dispatch on
   the arguments if it needs to distinguish elements. See `src/clay_perl.h`
   for the design note.
5. **Text is copied into a chunked per-context string arena whose chunks
   never move.** Clay reads a text element's string again in
   `Clay_EndLayout`, and keeps it longer for elements with an exit
   transition: `Clay_EndLayout` copies their subtree into the next
   frame, an element starts exiting in the first frame it is no longer
   declared (with the previous frame's text), and it keeps rendering its
   old text until the exit finishes. So the previous frame's chunks live
   one extra frame, and while any exit transition runs every chunk is
   kept (memory only grows during exit animations). Element id strings
   are interned (Clay stores `stringId` in its hash map and
   `pointerOverIds`) and swept after two unused frames. Never hand Clay a
   pointer into a Perl SV buffer that it may keep.
6. **Clay forgets hover callbacks on re-declaration.**
   `Clay__AddHashMapItem` clears an element's `onHoverFunction` whenever
   the element is declared again, so `Clay_OnHover` must be called every
   frame. `Clay_SetPointerState` runs the callbacks registered while
   declaring the last completed frame. The Perl-side registry keeps
   entries for two frames only to reclaim memory; it gives no grace
   period.
6a. **Callback exceptions are deferred, never swallowed.** Every
   trampoline makes one `G_EVAL` call into `Clay::XS::_dispatch`, which
   calls the Perl callback and parses its result; failures are stashed on
   the context and re-thrown by the XS wrapper after Clay returns
   (`Clay_EndLayout`, `Clay_SetPointerState`, the next `Clay_BeginLayout`
   for an abandoned frame, and every non-construction wrapper). Never let
   a croak escape from code Clay calls.
6b. **Open/close balance is tracked per context** (`in_frame`,
   `open_depth`). Closing or configuring with nothing open croaks;
   `Clay_EndLayout` auto-closes leftovers so Clay stays consistent, then
   croaks.
6c. **Callbacks cannot re-enter Clay.** `call_dispatcher` counts running
   callbacks in the thread-local `clay_perl_callback_depth`; while it is
   non-zero every wrapper that changes Clay's state (`REQUIRE_CONTEXT`,
   plus `Clay_Initialize`, `Clay_SetCurrentContext`, the count setters and
   DESTROY of the running context) croaks "cannot be called from inside a
   Clay callback", and that croak comes back as a deferred callback error.
   Read-only queries use `REQUIRE_CONTEXT_QUERY`. Both guards pin the
   context (a mortal reference to its referent) so a callback dropping
   the last reference frees it only after the calling statement. The
   dispatch kind and C result slot travel in the thread-local
   `clay_perl_pending_dispatch`, never through Perl arguments;
   `Clay::XS::_dispatch` croaks when called any other way. A new
   wrapper that calls into Clay must use one of the two guards.
7. **The C `CLAY()` / `CLAY_TEXT()` macros have no Perl analog.** They
   expand to control-flow tricks tied to C `for`-loops. Use the
   open / configure / close primitives instead. See the POD in
   `lib/Clay/XS.pm` for the mapping table.

## Repo conventions

- All Perl files start with:
  ```perl
  use v5.22;
  use warnings;
  use feature 'signatures';
  no warnings 'experimental::signatures';
  ```
- Function and struct names mirror C exactly (`Clay_Initialize`,
  `Clay__OpenElement`). Helpers that replace un-bindable C macros use
  snake_case (`sizing_fit`, `padding_all`, `corner_radius_all`).
- Hash keys for marshalled structs use the exact camelCase field names
  from clay.h (`backgroundColor`, `cornerRadius`, `layoutDirection`).
- Tests use `Test2::V0`. The smoke test in `t/00-load.t` doubles as the
  constants-loaded check.
- Render commands are returned as plain `AoH`


## Clay::UI invariants

1. Widgets are Object::Pad classes; the `class` keyword opens a fresh
   package, so `use Clay::XS qw(...)` at file scope does NOT seed
   helper subs inside the class block. Either qualify
   (`Clay::XS::sizing_fixed(...)`) or `use` again inside the body.
2. `Clay::UI::Role::Core::Element::to_config` discovers contributor methods
   via `Object::Pad::MOP::Class->all_methods` (roles, the class and its
   superclasses), de-duplicated, sorted by name and cached per class.
   Each mixin role provides one method named `contribute_<slice>(\%config)`,
   called exactly once per `to_config`. Names must be unique across
   composed roles (Object::Pad role composition errors on method
   conflict). Contributors must be order-independent: shared slices are
   merged (`HasLayout` merges the user's `layout` over whatever is there,
   `Clay::UI::Grid`'s `contribute_grid_defaults` merges its defaults under
   it); if two unrelated contributors write the same key, the
   alphabetically last one wins.
3. Classes can also define `contribute_*` methods directly; they are
   discovered like role methods, including in subclasses of that class.
4. Text leaves consume `Clay::UI::Role::Core::TextNode`; the walker
   dispatches them to `Clay__OpenTextElement` instead of the normal
   open/configure/close trio and ignores their `children`.
5. **Clay::UI registers no `Clay_OnHover` callbacks.** `render` works
   out the widgets under the pointer itself: after
   `Clay_SetPointerState` it maps `Clay_GetPointerOverIds` (which Clay
   fills under exactly the condition it uses to call hover callbacks)
   through the element-id registry of the last committed frame, reads
   `Clay_GetPointerState` (already updated for this frame), runs
   `Clay_UpdateScrollContainers`, updates the hovered / armed / pressed
   flags on the widgets and fires OnHoverStopped, OnHoverStart, OnPress,
   OnRelease and OnScroll - all before `Clay_BeginLayout`, with no
   element open, so listeners may change the tree. Every queued event
   fires even if a listener dies; the layout pass still runs (after
   `Clay_UpdateScrollContainers` a frame without a layout makes Clay drop
   every container's scroll state at the next update) and the first
   listener error is rethrown afterwards. Press and release go to one origin (the innermost Pressable of
   the topmost stack); a release only reaches an armed widget. The
   per-widget state lives in the Hoverable / Pressable roles; the
   orchestration in `Clay::UI::_dispatch_pointer_events`.
6. Clay's pointer-state struct is zero-initialised, which equals
   `CLAY_POINTER_DATA_PRESSED_THIS_FRAME`. The `Clay::UI` constructor
   settles it with `Clay_SetPointerState({ x => -1, y => -1 }, 0)`, so
   no warm-up frame is needed. Pointer tests still need one `render`
   before the pointer frame: Clay tests the pointer against the previous
   layout.
7. **Clay::UI stamps itself onto the root widget at construction time
   (`HasParent::_set_ui_controller`).** Every widget reaches its
   controller via `$widget->ui`, which walks `parent` to the topmost
   node and returns the stamped weak reference. The slot is write-once
   per root - a root cannot be re-bound to a second Clay::UI. This is
   the only widget-to-controller back-channel; nothing else in the
   walker carries it.
8. **Focus events (`OnFocus` / `OnBlur`) fire from
   `Clay::UI::set_focused_widget`, NOT from `render`.** They are
   driven by programmatic / input-handler focus changes (and by removing
   the subtree holding the focused widget), never by the layout pass.
   Setting focus to the already-focused widget is a no-op (no events
   refire). Undef-to-undef is also a no-op. The target is validated
   first, then `$_focused` and both `focused` states change, then OnBlur
   and OnFocus fire (drain-then-rethrow, like pointer events).
9. **HasFocusOrder delegation walks up from the currently focused
   widget; the *nearest* ancestor (including the focused widget
   itself) that composes the role takes over.** With nothing focused,
   the root takes over if it composes the role. Its
   `get_next_focus` / `get_previous_focus` is called with no
   arguments and must return either a Focusable widget belonging to
   the same tree or undef (no change; a widget whose `can_focus` is
   false also means no change); anything else dies naming the class.
   The default chain locates the focused widget among all Focusables
   (focusable right now or not) and scans on from there, wrapping.
   The `default_next_focus` /
   `default_previous_focus` helpers on the role re-enter Clay::UI's
   default depth-first chain, bypassing the HasFocusOrder
   consultation - this is how custom orders defer to default for
   parts of their subtree.
10. The walker injects `user_data => refaddr($widget)` into a copy of
   every element and text config and keeps a per-instance weak registry
   so `$ui->widget_for($cmd->{userData})` can recover the originating
   widget from a render command. A widget's `to_config` (or
   `text_config`) that sets `user_data` itself triggers a fail-loud
   error - pick one mechanism. Only the config is built before
   `Clay__OpenElementWithId`; everything after the open (marshalling in
   `Clay__ConfigureOpenElement`, the scroll offset, the children) runs
   inside one `eval`, `Clay__CloseElement` always runs, and the first
   error is rethrown afterwards. Once `Clay_UpdateScrollContainers` has
   run, `render` always runs the layout pass, even after a listener died;
   the layout pass calls `Clay_EndLayout` on every path after
   `Clay_BeginLayout` and clears its staged registries; the XS balance
   guards turn any remaining imbalance into a croak. `render` cannot be
   re-entered.
11. **`Element` has no public child mutators; `Container` does.**
   `Clay::UI::Role::Core::Element` keeps the children behind internal
   primitives (`_attach_children`, `_splice_children`, `_detach_children`)
   that validate the whole argument list before writing (widget type,
   duplicates, cycles, Clay::UI roots, earlier attachment) and detach
   what they remove. `children` returns a copy. `Container` (composed by
   `Box`, `Grid::Cell`, `HasScroll`) adds `add_child` and the removal
   methods on top; `Grid` and `Grid::Row` use the primitives directly.
   Object::Pad cannot override a composed role method, which is why the
   public mutators live in a separate role.
12. **A widget is attached at most once, ever.** `HasParent` keeps a
   permanent "was parented" flag; removal clears the `parent` slot (so
   the removed subtree has no `ui`) but not the flag. Before detaching,
   the parent tells its controller (`Clay::UI::_subtree_detached`), which
   blurs a focused widget inside the leaving subtree.
13. **Widget attributes are validated where they are set.** Roles use
   hand-written accessors (read with no argument, write and return with
   one) and `ADJUST` checks built on `Clay::UI::_validate`, whose
   known-key tables mirror exactly what `src/marshal.c` reads. Numeric
   ranges stay in XS; the only UI-level range is user sizing-group ids
   (`0 .. 2**20 - 1`), which keeps them apart from `Clay::UI::Grid`'s
   packed ids (set through the internal `_set_grid_groups`). User ids
   must not start with `anon:`, the prefix of the ids `resolve_id`
   derives for widgets without one. Classes in this distribution, and the
   classes in their SYNOPSIS blocks, are `:strict(params)`.

## Bumping Clay versions

1. Drop the new upstream `clay.h` into both `references/clay/clay.h` and
   `src/clay/clay.h.orig`.
2. `rm -f src/clay/clay.h && make`. If the patch applies cleanly you're
   done. If not, `patch` leaves `src/clay/clay.h.tmp` and
   `src/clay/clay.h.tmp.rej`; resolve the rejects by hand in
   `clay.h.tmp`, move it to `src/clay/clay.h`, then re-derive the patch with
   `diff -u --label a/src/clay/clay.h --label b/src/clay/clay.h
   src/clay/clay.h.orig src/clay/clay.h > patches/0001-clay-sizing-groups.patch`.
3. Regenerate fixtures if layout output drifted:
   `CLAY_UI_UPDATE_FIXTURES=1 prove -lb t/99-golden.t`. Inspect the
   diff before committing - drifts unrelated to the bump indicate a
   regression in our patch interaction with the new upstream code.
4. Preserve the `#define CLAY_IMPLEMENTATION`-in-one-file invariant (#3
   above) and the `#pragma GCC diagnostic ignored` lines around the
   include in `src/clay_impl.c`.

## Pointers when something breaks

- Build fails on second `.c` file: the postamble was removed or renamed.
  Check `Makefile.PL`.
- `Could not find a typemap`: the `typemap` file moved or a new fixed-width
  int type is used as an XS return type. Update `typemap`.
- Segfault on second `Clay_Initialize`: re-read invariant #1 above.
- Hover/scroll test that worked yesterday now fails: a previous test left
  the context in a non-reset state, or you skipped the prior-frame
  pattern. Initialise a fresh context in each `subtest` when possible.
- `Clay_EndLayout` (or `Clay_SetPointerState`) dies with a message from
  your own callback: a callback threw while Clay was running and the
  error was re-thrown once Clay returned. `(and N more callback errors
  this frame)` counts the errors after the first; `(from the previous
  unfinished frame)` means a frame was abandoned before `Clay_EndLayout`.
- `N element(s) still open at Clay_EndLayout`: an exception (or a
  missing `Clay__CloseElement`) left elements open; the frame was
  discarded and the next one works.
- `element/word counts changed since Clay_Initialize`: a capacity setter
  ran on a live context; call `Clay_Initialize` again.
- `not a live Clay::XS::Context` / `different interpreter/thread`: a
  copied, forged, destroyed or foreign context object was used.
